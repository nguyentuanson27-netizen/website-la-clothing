# Permanent domain cutover — `www.lafashion.asia`

Status: **OWNER-APPROVED TARGET / EXTERNAL CUTOVER NOT YET EVIDENCED**

Authority: ADR 0009. This runbook changes no external system by itself.

## Target state

- canonical production hostname: `www.lafashion.asia`
- storefront origin: `https://www.lafashion.asia`
- target `APP_DOMAIN=www.lafashion.asia`
- target `BETTER_AUTH_URL=https://www.lafashion.asia`
- `SEARCH_INDEXING_ENABLED=false` through the cutover and verification phase
- legacy temporary host: `la.lanadesign.vn`, retained as non-indexable containment/rollback origin
- apex `lafashion.asia`: not canonical; redirect behavior must be observed before it is documented as active

Domain selection does **not** complete U35, U41, Gate S, Merchant verification, Search Console verification, or organic indexing activation.

## Pre-cutover checks

Before changing public traffic:

1. Record the exact reviewed repository SHA to deploy.
2. Confirm ownership/control of DNS for `lafashion.asia`.
3. Prepare `www.lafashion.asia` DNS to the approved public edge; record the actual record type/value without publishing secrets.
4. Prepare nginx-proxy-manager/TLS for `www.lafashion.asia` and the existing internal Caddy upstream.
5. If an apex redirect is desired, configure `lafashion.asia` only as a redirect source to `https://www.lafashion.asia`; do not make the apex a second application origin.
6. Prepare the production environment with matching values:
   - `APP_DOMAIN=www.lafashion.asia`
   - `BETTER_AUTH_URL=https://www.lafashion.asia`
   - `SEARCH_INDEXING_ENABLED=false`
7. Keep Merchant market authority at reviewed `VN` / `vi` / `VND` and do not change GTM/promotion/indexing gates as part of the domain switch.
8. Run the normal release preflight on the exact deployment SHA.

## Cutover verification

After DNS/edge/VPS changes are actually applied, collect observed evidence for all of the following before calling the domain live:

- `https://www.lafashion.asia/` resolves and serves the expected application over valid HTTPS;
- `/shop`, one representative PDP, `/returns`, `/shipping`, and `/size-guide` serve successfully;
- auth base URL/origin behavior remains on `https://www.lafashion.asia`;
- `https://www.lafashion.asia/feeds/google-merchant` returns the expected public Merchant RSS when the reviewed Merchant market environment is present;
- representative product landing URLs and images generated by the Merchant feed use `https://www.lafashion.asia`;
- request `Host`/forwarded-host/query noise cannot replace the server-owned origin;
- with `SEARCH_INDEXING_ENABLED=false`, HTML remains `noindex, nofollow`, canonical links remain withheld, and sitemap advertising remains disabled under the existing policy;
- `/robots.txt` preserves the reviewed crawl boundary and does not block Merchant landing/image/feed paths;
- if apex redirect is configured, `https://lafashion.asia/...` redirects to the matching `https://www.lafashion.asia/...` destination without becoming a second rendered origin;
- the legacy `la.lanadesign.vn` host is not indexable and does not advertise canonical/sitemap authority.

Do not infer any item from repository configuration alone; record the observed HTTP/DNS/TLS result.

## Search / U35 handoff

Once the permanent host is serving production traffic reliably, U35 may proceed with permanent-domain verification in Search Console/Bing/Merchant as applicable. Verification does not itself approve indexing.

Gate S remains separate. Immediately before any later `SEARCH_INDEXING_ENABLED=true` change, rerun all activation-time search/capacity checks required by `docs/operations/p12-search-exposure.md` on the exact activation head and obtain explicit human approval.

## Merchant / U41 handoff

After the permanent host is observed live, use the permanent URLs for Merchant external setup:

- website: `https://www.lafashion.asia`
- feed: `https://www.lafashion.asia/feeds/google-merchant`
- return policy: `https://www.lafashion.asia/returns`
- shipping policy: `https://www.lafashion.asia/shipping`

Merchant Center account state, website claim, Scheduled Fetch, Diagnostics, Automations, and Ads linkage remain external evidence and must not be marked complete from this PR.

## Rollback

If buyer-critical verification fails:

1. keep `SEARCH_INDEXING_ENABLED=false`;
2. restore the last reviewed working public-edge/VPS routing;
3. if needed, temporarily restore matching legacy values for both `APP_DOMAIN` and `BETTER_AUTH_URL`;
4. verify buyer-critical pages and checkout before reopening traffic;
5. keep `la.lanadesign.vn` non-indexable;
6. fix the cutover issue and repeat this checklist.
